# Opportunity@Work AI Skill File — Board & Senior Leadership Instruction Sheet

**Prepared:** March 21, 2026
**Audience:** Board of Directors & Senior Leadership

---

## What Is a Skill File?

A skill file is a structured knowledge document designed to be consumed by AI assistants (such as Claude, ChatGPT, Copilot, and custom AI applications). When loaded into an AI session, the skill file gives the AI deep, accurate, and up-to-date institutional knowledge — effectively turning a general-purpose AI into an Opportunity@Work subject-matter expert.

Think of it as a "briefing book" that an AI reads before every conversation, ensuring it can speak fluently and accurately about our mission, data, programs, and impact.

| **Internal Q&A** | Any team member can ask questions like "How many STARs are in the healthcare sector?" or "What did the State of the Paper Ceiling report find about wage gains?" and get sourced answers instantly. |

## How to Use It Today

### For Individual Use (No Technical Setup Required)

1. **Open an AI assistant** (Claude, ChatGPT, or similar)
2. **Upload or paste** the `opportunity-at-work.skill.md` file at the start of your conversation
3. **Ask questions or request outputs** — the AI will respond with full organizational context

**Example prompts to try:**
- "Summarize our key findings from the State of the Paper Ceiling report in three bullet points for a funder meeting."
- "Draft a one-paragraph description of STARs for a government audience."
- "What are the latest metrics on jobs opened to STARs through the Public Sector Hub?"
- "Compare the findings of Navigating with the STARs and Rise with the STARs."
- "Write a LinkedIn post announcing our Lightcast partnership."

### For Team Use (Light Technical Setup)

- **Claude Projects / ChatGPT Custom GPTs:** Upload the skill file as a project knowledge file so it persists across all conversations for the team.
- **Shared drive:** Place the file in a shared location (Google Drive, SharePoint) with instructions for team members to upload it into their AI sessions.

## Releasing to a Broader Audience

### Recommended Phased Approach

#### Phase 1 — Internal Pilot (Weeks 1–4)

**Goal:** Validate accuracy and usefulness before external release.

- Distribute the skill file to 10–15 internal staff across Communications, Development, Policy, and Partnerships.
- Collect feedback on accuracy, gaps, and most valuable use cases.
- Update the skill file based on feedback (correct any errors, add missing data, refine terminology).
- Establish an owner responsible for maintaining and versioning the file.

**Success criteria:** Staff report time savings; no factual errors flagged; at least 3 use cases validated.

#### Phase 2 — Coalition Partners (Weeks 5–8)

**Goal:** Enable partners to accurately represent STARs and our work.

- Share the skill file with Tear the Paper Ceiling coalition leads and STARs Public Sector Hub anchor partners.
- Include a brief usage guide (can be derived from this document).
- Offer an optional 30-minute walkthrough session.
- Gather partner feedback to identify what additional context they need.

**Success criteria:** Partners independently generate accurate content; positive feedback on utility.

#### Phase 3 — Public Release (Weeks 9–12)

**Goal:** Maximize reach and position Opportunity@Work as an AI-forward organization.

- Publish the skill file on opportunityatwork.org (e.g., under Resources or the Research Hub).
- Announce via blog post, newsletter, and social channels.
- Frame the release around the narrative: *"We're making it as easy as possible for anyone — employers, policymakers, researchers, advocates — to understand and act on STARs data."*
- Consider publishing on GitHub as an open-source resource for the workforce development community.
- Optionally submit to AI skill/knowledge directories and workforce development platforms.

**Distribution channels for public release:**
- Opportunity@Work website (downloads / resources page)
- GitHub repository (open source, version-controlled)
- Partner newsletters and networks
- LinkedIn and social media announcements
- Workforce development conferences and convenings
- Direct distribution to state workforce agencies

## Maintenance & Governance

### Keeping the Skill File Current

| Activity | Frequency | Owner |
|----------|-----------|-------|
| Review for accuracy | Quarterly | Communications / Research |
| Add new report findings | As reports are published | Research team |
| Update metrics and milestones | Quarterly | Impact / Data team |
| Update technology platform info | As platforms evolve | Product team |
| Update partnership roster | Semi-annually | Partnerships team |
| Version control and changelog | With every update | Designated file owner |

### Quality Controls

- **Single source of truth:** The skill file should be the authoritative AI knowledge document. Avoid creating competing versions.
- **Version numbering:** Use semantic versioning (v1.0, v1.1, v2.0) so users know when content has changed.
- **Review process:** Any updates should be reviewed by at least one subject-matter expert before publication.
- **Sourcing:** All claims in the skill file link back to published Opportunity@Work research or official communications.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| AI generates inaccurate statements using the skill file | Quarterly accuracy reviews; clear sourcing for all data points; disclaimer that AI outputs should be verified for high-stakes use. |
| Outdated information persists in circulated copies | Version numbering; central download location; email notifications when new versions are published. |
| External parties misrepresent our data | Include a brief usage license/terms specifying attribution requirements and prohibiting modification of core data claims. |
| Sensitive or pre-publication data accidentally included | Establish a review checklist before each release; only include publicly available information. |
